# archeology-doc website

[English](#english) · [Español](#español)

## English

Static page (HTML + CSS + JS, no build step, no dependencies): what the project is, how it works,
installation, commands, supported agents and the VS Code extension. Automatic light/dark theme
(◐ button). The logo has two versions: `assets/logo.png` (light backgrounds) and
`assets/logo-dark.png` (light text, for dark backgrounds); `assets/icon.png` is the app icon. These are the
sources: the page uses the optimized sizes generated by `scripts/make-images.mjs` (`logo-*.webp`,
`icon-64.*`, `favicon-32/16.png`, `apple-touch-icon.png`, `icon-192.png`, `og-image*.png`).

### Languages (English / Spanish)

The page is available in English and Spanish, each with its own indexable URL: `/` (English,
`index.html`) and `/es/` (Spanish), with an **EN | ES** switcher in the header.

- `index.html` is the English page. `scripts/prerender.mjs` (no dependencies) generates
  `/es/index.html` from it by applying the `es` dictionary of `i18n.js` server-side: `<html lang="es">`,
  Spanish title/description/Open Graph, canonical `https://archeology-doc.com/es/` and `../` asset paths.
  `scripts/build.sh` runs it into `dist/site/` (also writing the English page with the published
  version in its JSON-LD and `sitemap.xml` with today's `lastmod`).
- The switcher links navigate between `/` and `/es/` keeping the `#anchor` and remember the choice
  (`localStorage` `adoc-lang`). There is no automatic redirect by browser language: if the browser
  prefers the other language and nothing is stored, a small dismissible notice offers it. Old
  `?lang=en|es` links go to the matching page.
- Markup: `data-i18n="key"` (text), `data-i18n-html="key"` (fixed strings with inline markup such
  as `<code>`), `data-i18n-attr="attr:key;attr2:key2"` (`title`, `aria-label`, `content`, `href`…).
  Texts generated by `main.js` use `AdocI18n.t('js.…')` in the page language.
- Structured data (schema.org JSON-LD: SoftwareApplication, WebSite, WebPage, SoftwareSourceCode and
  the FAQPage of the visible FAQ) is generated from the dictionaries by `prerender.mjs`; after
  changing `meta.*` or `faq.*` keys run `node WEBSITE/scripts/prerender.mjs --sync-source`.
- Check: `node WEBSITE/scripts/check-i18n.mjs` verifies that both dictionaries have the same keys,
  that every key used in `index.html` / `main.js` / `i18n.js` exists, that the default HTML matches the
  English dictionary, that the generated Spanish page has no untranslated keys and that the JSON-LD
  is valid and up to date. `dist.sh` and `build.sh` run it.
- Images: `scripts/make-images.mjs` (macOS `sips` + Chrome via Playwright) regenerates the WebP/PNG
  sizes of the logo, the favicons and the 1200×630 social cards (`og-image*.png`).

The installers follow the system locale (Spanish if `LC_ALL` / `LC_MESSAGES` / `LANG` starts with
`es`, or if the Windows UI culture is Spanish; English otherwise). Override with
`ADOC_LANG=en|es`.

### View locally

```bash
node WEBSITE/scripts/prerender.mjs                     # generates WEBSITE/es/ (git-ignored)
python3 -m http.server -d WEBSITE 8080                  # http://localhost:8080 and /es/
```

### Downloads and installers

The “Install” section detects the operating system and shows the matching command:

- macOS / Linux: `curl -fsSL https://archeology-doc.com/download/install.sh | sh`
- Windows: `irm https://archeology-doc.com/download/install.ps1 | iex`

The commands use the URL the page is opened from. The installers download the binary from
`/download`, verify its SHA-256 against `SHA256SUMS` and install it without requiring Rust. The
downloads table is filled from `download/latest.json`.

`/download` is generated, not versioned:

```bash
WEBSITE/dist.sh --base-url https://archeology-doc.com/download   # native macOS + Linux/Windows in Docker
python3 -m http.server -d WEBSITE 8080               # test at http://localhost:8080
```

### Publishing

The site is hosted on **Cloudflare Pages** at <https://archeology-doc.com>. One-time setup:

1. Cloudflare → *Workers & Pages → Create → Pages → Direct Upload*: create the project
   `archeology-doc` (upload any file once; the workflow deploys afterwards).
2. In the project: *Custom domains → Set up a custom domain* → `archeology-doc.com` (and
   `www.archeology-doc.com` if wanted). The domain is already on Cloudflare, so DNS and the
   certificate are configured automatically.
3. Cloudflare → *My Profile → API Tokens → Create Token* with the permission
   *Account → Cloudflare Pages → Edit*.
4. GitHub → *Settings → Secrets and variables → Actions*: secrets `CLOUDFLARE_API_TOKEN` and
   `CLOUDFLARE_ACCOUNT_ID`. Optional variables: `SITE_URL` (default `https://archeology-doc.com`)
   and `CLOUDFLARE_PAGES_PROJECT` (default `archeology-doc`).

`_headers` serves the installers as text with a short cache. Every `v*` tag runs `.github/workflows/release.yml`: it checks that the tag matches the version in
`Cargo.toml`, builds the five platforms, creates the release and publishes the site with
`/download` included (without `dist.sh`, `scripts/`, the `README.md` files or `installers/`, which
still carry the URL placeholder).

On other static hosting (Netlify, S3, GitHub Pages) run `WEBSITE/dist.sh --base-url …` and
upload `WEBSITE/` without `dist.sh`, `scripts/`, `README.md` or `installers/`.

### Idiomas (inglés / español)

La página está en inglés y español, cada idioma con su URL indexable: `/` (inglés,
`index.html`) y `/es/` (español), con un selector **EN | ES** en la cabecera.

- `index.html` es la página en inglés. `scripts/prerender.mjs` (sin dependencias) genera

  (`localStorage` `adoc-lang`). No hay redirección automática por idioma del navegador: si el navegador
  prefiere el otro idioma y no hay elección guardada, un aviso discreto lo ofrece y se puede cerrar.
  Los enlaces antiguos `?lang=en|es` llevan a la página correspondiente.
- Marcado: `data-i18n="clave"` (texto), `data-i18n-html="clave"` (cadenas fijas con marcado como

- Datos estructurados (JSON-LD de schema.org: SoftwareApplication, WebSite, WebPage, SoftwareSourceCode
  y el FAQPage de las preguntas frecuentes visibles): los genera `prerender.mjs` desde los
  diccionarios; tras cambiar claves `meta.*` o `faq.*` ejecuta `node WEBSITE/scripts/prerender.mjs --sync-source`.
- Comprobación: `node WEBSITE/scripts/check-i18n.mjs` verifica que ambos diccionarios tengan las
  mismas claves, que existan todas las claves usadas en `index.html` / `main.js` / `i18n.js`, que el HTML
  por defecto coincida con el diccionario en inglés, que la página en español no deje claves sin
  traducir y que el JSON-LD sea válido y esté al día. `dist.sh` y `build.sh` lo ejecutan.
- Imágenes: `scripts/make-images.mjs` (`sips` de macOS + Chrome con Playwright) regenera los tamaños
  WebP/PNG del logo, los favicons y las tarjetas sociales 1200×630 (`og-image*.png`).

Los instaladores siguen el idioma del sistema (español si `LC_ALL` / `LC_MESSAGES` / `LANG`
empieza por `es`, o si la cultura de Windows es española; inglés en otro caso). Se fuerza con
`ADOC_LANG=en|es`.

1. Cloudflare → *Workers & Pages → Create → Pages → Direct Upload*: crea el proyecto

4. GitHub → *Settings → Secrets and variables → Actions*: secrets `CLOUDFLARE_API_TOKEN` y
   `CLOUDFLARE_ACCOUNT_ID`. Variables opcionales: `SITE_URL` (por defecto
   `https://archeology-doc.com`) y `CLOUDFLARE_PAGES_PROJECT` (por defecto `archeology-doc`).

plataformas, crea el release y publica el sitio con `/download` (sin `dist.sh`, `scripts/`, los
`README.md` ni `installers/`). En otro hosting estático, ejecuta `WEBSITE/dist.sh --base-url …` y
