# archeology-doc website

[English](#english) · [Español](#español)

## English

Static page (HTML + CSS + JS, no build step, no dependencies): what the project is, how it works,
installation, commands, supported agents and the VS Code extension. Automatic light/dark theme
(◐ button). The logo has two versions: `assets/logo.png` (light backgrounds) and
`assets/logo-dark.png` (light text, for dark backgrounds); `assets/icon.png` is the app icon and
`favicon.png` the favicon.

### Languages (English / Spanish)

The page is available in English and Spanish, with an **EN | ES** switcher in the header.

- The HTML ships in English (what crawlers and no-JS visitors see). `i18n.js` holds the `en` and
  `es` dictionaries and is loaded in `<head>`, so the language is resolved before the first paint.
- Initial language: `?lang=en|es` > choice saved in `localStorage` (`adoc-lang`) >
  `navigator.languages` (first `es*` or `en*`) > `en`.
- Markup: `data-i18n="key"` (text), `data-i18n-html="key"` (fixed strings with inline markup such
  as `<code>`), `data-i18n-attr="attr:key;attr2:key2"` (`title`, `aria-label`, `content`…).
  Texts generated by `main.js` use `AdocI18n.t('js.…')` and are repainted on the
  `adoc:langchange` event.
- Check: `node WEBSITE/scripts/check-i18n.mjs` verifies that both dictionaries have the same keys,
  that every key used in `index.html` / `main.js` exists, and that the default HTML matches the
  English dictionary. `dist.sh` runs it automatically when `node` is available.

The installers follow the system locale (Spanish if `LC_ALL` / `LC_MESSAGES` / `LANG` starts with
`es`, or if the Windows UI culture is Spanish; English otherwise). Override with
`ADOC_LANG=en|es`.

### View locally

```bash
open WEBSITE/index.html                 # macOS
# or with a server: python3 -m http.server -d WEBSITE 8080  →  http://localhost:8080
#                   http://localhost:8080/?lang=es          →  Spanish
```

### Downloads and installers

The “Install” section detects the operating system and shows the matching command:

- macOS / Linux: `curl -fsSL https://archeology-doc.com/download/install.sh | sh`
- Windows: `irm https://archeology-doc.com/download/install.ps1 | iex`

The commands use the URL the page is opened from. The installers download the binary from
`/download`, verify its SHA-256 against `SHA256SUMS` and install it without requiring Rust. The
downloads table is filled from `download/latest.json`.

`/download` is generated, not versioned:

```bash
WEBSITE/dist.sh --base-url https://archeology-doc.com/download   # native macOS + Linux/Windows in Docker
python3 -m http.server -d WEBSITE 8080               # test at http://localhost:8080
```

### Publishing

The site is hosted on **Cloudflare Pages** at <https://archeology-doc.com>. One-time setup:

1. Cloudflare → *Workers & Pages → Create → Pages → Direct Upload*: create the project
   `archeology-doc` (upload any file once; the workflow deploys afterwards).
2. In the project: *Custom domains → Set up a custom domain* → `archeology-doc.com` (and
   `www.archeology-doc.com` if wanted). The domain is already on Cloudflare, so DNS and the
   certificate are configured automatically.
3. Cloudflare → *My Profile → API Tokens → Create Token* with the permission
   *Account → Cloudflare Pages → Edit*.
4. GitHub → *Settings → Secrets and variables → Actions*: secrets `CLOUDFLARE_API_TOKEN` and
   `CLOUDFLARE_ACCOUNT_ID`. Optional variables: `SITE_URL` (default `https://archeology-doc.com`)
   and `CLOUDFLARE_PAGES_PROJECT` (default `archeology-doc`).

`_headers` serves the installers as text with a short cache. Every `v*` tag runs `.github/workflows/release.yml`: it checks that the tag matches the version in
`Cargo.toml`, builds the five platforms, creates the release and publishes the site with
`/download` included (without `dist.sh`, `scripts/`, the `README.md` files or `installers/`, which
still carry the URL placeholder).

On other static hosting (Netlify, S3, GitHub Pages) run `WEBSITE/dist.sh --base-url …` and
upload `WEBSITE/` without `dist.sh`, `scripts/`, `README.md` or `installers/`.

  `<code>`), `data-i18n-attr="attr:clave;attr2:clave2"` (`title`, `aria-label`, `content`…). Los

Los instaladores siguen el idioma del sistema (español si `LC_ALL` / `LC_MESSAGES` / `LANG`
