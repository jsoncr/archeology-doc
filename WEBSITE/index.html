archeology-doc (adoc) inspects new or legacy projects and, with the AI agent you already use, generates a browsable knowledge base, documentation, findings and context for agents. Every claim cites its source as path:line.

What archeology-doc gives you

🧭

System map

Modules, features, glossary and decisions in plain Markdown, browsable in Obsidian, VitePress or GitHub.

🔎

Contradictions and risks

Findings by severity: outdated documentation, duplicated rules, conflicting configuration, dead code.

🧪

Testing gaps

Features ↔ tests, covered and missing scenarios, disabled or empty tests.

🤖

Context for agents

AGENTS.md, persistent memory and skills: every AI session starts knowing what exists and where.

📐

Specs with OpenSpec

Requirement compliance checked against the code, with abandoned changes flagged in review, status and check.

✅

Verifiable

adoc check validates evidence, links and outdated notes; ideal for CI.

How it works

Rust computes the deterministic parts; your agent does the interpretation; adoc orchestrates and validates.

  1. 1

    adoc scan

    AI-free inventory: languages, modules, tests, CI, git history and OpenSpec. Honors .gitignore and excludes secrets.

  2. 2

    adoc plan

    Splits the work into bounded tasks based on project size: a few tasks for a small one, more for a large one.

  3. 3

    adoc inspect

    Your agent runs each task. It is only marked done if it produced what was asked, with valid evidence.

  4. 4

    adoc preview

    A site with a dashboard: status, findings, questions for the team and FAQ. Or a single HTML report.

  5. 5

    adoc sync

    When the code changes, it marks the affected notes as outdated and reopens only those tasks.

Install

One command for your system: it downloads the binary for your platform, verifies its SHA-256 and puts it on your PATH. No Rust needed. Node 18+ only for the VitePress site and the extension.

Terminal

$ curl -fsSL https://archeology-doc.com/download/install.sh | sh

or download the binary

Apple Silicon (M1–M4) Intel

When downloaded from the browser, macOS quarantines it: xattr -d com.apple.quarantine adoc archeology-doc, then move both to ~/.local/bin. Not needed with the terminal command.

Terminal

$ curl -fsSL https://archeology-doc.com/download/install.sh | sh

or download the binary

x86_64 ARM64

Binaries for glibc 2.28 or later (Debian 10, Ubuntu 18.10, RHEL 8 and newer).

PowerShell

> irm https://archeology-doc.com/download/install.ps1 | iex

or download the binary

Windows x64 (.zip)

The installer puts it in %LOCALAPPDATA%\Programs\archeology-doc\bin and adds it to your PATH, without administrator rights. On Windows ARM64 it runs under x64 emulation.

# Requires Rust (rustup.rs). Installs `adoc` into ~/.cargo/bin

# Only checks whether a new version is available

# Downloads and installs the new version automatically

Stay up to date: adoc upgrade checks for a new version and updates itself automatically; adoc upgrade --check only checks, without changing anything.

Two equivalent binaries are installed: adoc (short) and archeology-doc. To uninstall: adoc uninstall (with --purge it also deletes ~/.archeology-doc; your project files are never touched).

Getting started

In your project folder:

cd my-project

adoc init                 # config + structure
adoc agent use claude     # or devin, codex, gemini…
adoc scan                 # deterministic inventory
adoc plan                 # tasks sized to the project
adoc inspect              # the agent documents
adoc status               # where you are and what's next
adoc preview              # see the result

Day to day

adoc statusSummary: progress, pending tasks and the next step (--format json for integrations)
adoc reviewProgress, findings, features without tests
adoc checkChecklist of what is done and missing, with hints to fix it (exit code for CI)
adoc syncShows changed and uncovered files, marks outdated notes and reopens their tasks
adoc inspect --resumeRetries failed or interrupted tasks
adoc task answer T-014 "…"Answers an agent that asked a question
adoc task run T-014 -iInteractive session with the agent
adoc ask "…?"Ask about the project → FAQ
adoc graphInteractive knowledge graph in the browser; --json prints it as JSON
adoc reportSingle HTML report to share

Projects, agents and settings

adoc projects delete <name>Removes a project from the registry; with -d it also deletes its generated files

What stays in your project

Only results, in Markdown. Working state lives outside the repository.

├── archeology-doc.toml     # config + ID
├── AGENTS.md               # context for agents
├── knowledge/              # Obsidian vault
│   ├── 00-overview.md
│   ├── modules/  features/  findings/
│   ├── tests/  glossary/  faq/
│   └── memory/
├── docs/                   # VitePress site
└── llms.txt

Principles

  • Evidence first: every claim cites path:line
  • Non-destructive: never modifies your code; respects your edits
  • Local-first: nothing leaves your machine except what your agent sends
  • Incremental: small, resumable tasks, module by module
  • Standards: Markdown, OpenSpec, AGENTS.md, Obsidian and VitePress

Sensitive data stays out

archeology-doc never reads secret files and tells your agent not to either. This is what is left out by default:

🔐

Secret files skipped

.env*, *.pem, *.key, credentials*, SSH keys (id_rsa, id_ed25519…), keystores (*.p12, *.pfx, *.jks), .npmrc, .netrc, .git-credentials, *.tfvars, *.tfstate, secrets.*. They never reach the inventory or the prompts.

🔒

Can't be switched off

A repository's configuration can add patterns ([scan] secrets_patterns) but never remove the built-in ones.

🤖

Rules for the agent

Every task tells the agent not to read or cite those files, and never to copy keys, tokens, passwords or connection strings into the notes: only that they exist and where.

🗂️

Respects .gitignore

Plus vendor/, node_modules/, target/, dist/ and minified files. Add your own with [paths] exclude. Symbolic links are not followed.

🏠

Working state outside the repo

Tasks, logs and approvals live in ~/.archeology-doc/, not in your repository, and adoc never writes through a link that points outside the project.

🛡️

Your code isn't uploaded

adoc only talks to the network to check for updates (adoc upgrade, adoc doctor; turn it off with ADOC_NO_UPDATE_CHECK=1). The agent you choose talks to its own provider. Third-party adapters need your approval (adoc agent trust).

# archeology-doc.toml: added to the built-in rules
[scan]
secrets_patterns = ["*.vault", "config/prod.*"]

[paths]
exclude = ["**/fixtures/**", "legacy/generated/**"]

Detection works by file name: a secret hard-coded in regular source code can still reach the agent. The agent is told not to copy it, but rotate it anyway and move it to an excluded file.

Frequently asked questions

What is archeology-doc?

An open-source command-line tool (adoc) written in Rust that documents new or legacy codebases with the AI coding agent you already use. It generates a Markdown knowledge base, VitePress documentation, findings and an AGENTS.md with context for agents, and every claim cites its source as path:line.

Which AI agents does it work with?

Claude Code, Codex, Devin, Gemini CLI, Qwen Code, OpenCode, Cursor, GitHub Copilot, Amp, goose and Aider. Switch agent or model with adoc agent use; without a CLI agent, adoc agent use manual exports the tasks so you can do them by hand.

Does it upload my code or read my secrets?

No. adoc runs on your machine and only uses the network to check for updates (turn it off with ADOC_NO_UPDATE_CHECK=1); the agent you choose talks to its own provider, as it already does. Secret files such as .env*, *.pem or SSH keys are skipped and never reach the prompts. See what is left out.

Which programming languages and frameworks does it support?

It is language-agnostic: adoc scan detects the languages, modules, tests and CI in the repository, and your agent reads the code itself. It works with new or legacy projects, small or large.

Is it free?

Yes. archeology-doc is free and open source under the MIT license. The only cost is your AI agent’s usage, if your provider charges for it.

Is there a VS Code extension?

Yes: install archeology-doc from the Visual Studio Marketplace (jcruz.archeology-doc) or download the .vsix. It shows tasks, findings, the knowledge graph and questions in VS Code, Cursor, Windsurf and Devin Desktop.

How do I update it?

Run adoc upgrade: it downloads the latest version, verifies its SHA-256 and replaces the binaries. adoc upgrade --check only tells you whether a new version is available.
